In an exact System checkout, ordinary read-only checks are:

```bash
python scripts/validate_repository_registry.py governance/repository-registry.json
python scripts/validate_repository_state.py governance/repository-state.json
python scripts/refresh_repository_state.py --check-ledger
python scripts/run_repository_watchdog.py --check-current
python scripts/refresh_repository_state.py --refresh --scope Core
```

The existing GitHub Actions [Repository Drift Watchdog](https://github.com/aiverse-filmmakers/AI-Verse-System/actions/workflows/repository-drift-watchdog.yml) runs daily and on manual dispatch. It uses the one Registry-derived global refresh engine and publishes **only** System `governance/repository-state.json` and `docs/REPOSITORY-STATE-LEDGER.md` when all gates pass. Run it at a controlled exact System head for a new full-network decision. Do not hand-edit the generated ledger, relax completeness, exclude a registered repository, fabricate `WATCHDOG-CURRENT`, replace unavailable evidence with fixture success or force-push away a concurrent change.

For a component defect or intentional forward change: resolve the canonical owner first, modify the **owner** repo, pass owner-native CI/acceptance and descriptor at immutable refs, refresh the relevant System State scope, admit those exact refs to Distribution candidate, run compatibility/migration/preservation/composed qualification and only then consider an explicit promotion that persists its durable receipt. Bind every approval to exact Registry/State/owner/Distribution snapshots; requalify after any bound-input change. Use [Whole-Product Qualification](https://github.com/aiverse-filmmakers/AI-Verse-Distribution/blob/742176fe25fc67408626587e117851cdfc42d14f/docs/WHOLE-PRODUCT-QUALIFICATION.md), [Core Promotion Gate](https://github.com/aiverse-filmmakers/AI-Verse-Distribution/blob/742176fe25fc67408626587e117851cdfc42d14f/docs/CORE-PROMOTION-GATE.md), and [Durable Release Receipt](https://github.com/aiverse-filmmakers/AI-Verse-Distribution/blob/742176fe25fc67408626587e117851cdfc42d14f/docs/RELEASE-RECEIPT.md) instead of inventing a parallel gate.

If evidence is failed/stale or the watchdog reports an inaccessible surface, stop the affected decision, inspect exact repository ID/surface/kind diagnostics and authorization/visibility, resolve the actual source problem, then rerun the existing permitted gate.
