## 1. Purpose and non-claim

This file guarantees complete directional pair coverage for the 14-repository audit universe without pretending the relationships have already been proven.

A0.4 performs **enumeration only**.

It does **not**:
- classify any pair as REQUIRED, ALLOWED, FORBIDDEN or NONE;
- infer a relationship from architecture memory, existing System component specs or release composition;
- prove a seam merely because two components appear in the same release set;
- perform A1 standalone repository reconstruction;
- perform A2 seam resolution;
- patch product code or documentation.

Every off-diagonal pair and every relation dimension begins as **UNKNOWN**.

Self-relations are excluded from the 182 inter-repository pair count and are shown as **N/A** in the summary matrix.

## 3. Pair-state vocabulary

Allowed pair/dimension states from the protocol:

- **UNKNOWN** — not yet independently resolved.
- **REQUIRED** — current supported architecture requires the relation.
- **ALLOWED** — relation may exist but is not required for baseline operation.
- **FORBIDDEN** — architecture relies on the direct relation not existing.
- **NONE** — no current direct relationship is intended or found, with sensitive NONE requiring evidence.

A0.4 uses only **UNKNOWN** for inter-repository cells.

## 8. A1 extraction contract

During each standalone A1 repository audit, its packet must extract without resolving the matrix:

- outbound relationship claims;
- inbound relationship claims;
- forbidden dependency claims;
- owner/write-path claims;
- lifecycle/discovery dependencies;
- identity/scope dependencies;
- permission/approval assumptions;
- telemetry/cost assumptions;
- credential/effect assumptions;
- release/version/migration assumptions;
- health/readiness assumptions.

These become A2.1 inputs. A1 claims do not convert UNKNOWN matrix states by themselves.

## 9. A2.1 resolution contract

A2.1 must resolve all 182 directional pairs using independent A1 packets plus focused implementation evidence.

For each material resolved dimension, record:

- From
- To
- Dimension
- State
- Evidence
- Contract
- Observed implementation
- Tests
- Contradictions
- Finding IDs
- Last reviewed refs

Completion requires:
- all 182 directional pairs classified;
- every REQUIRED relation supported by an evidence path;
- every FORBIDDEN relation supported by enforcement/negative-space evidence;
- sensitive NONE relations supported by evidence;
- material unresolved UNKNOWN relations converted into findings;
- refs matching the accepted audit snapshot or an explicitly re-frozen replacement.

## 10. Sensitive seams pre-registered for later inspection

The protocol requires focused inspection, where relevant, of:

- Dashboard direct canonical-owner writes;
- Apps direct canonical-owner writes;
- Gateway durable semantic Memory ownership;
- Brain security/permission enforcement;
- Multiple Bots canonical Token pricing/cost ownership;
- Automations bypassing consent/permission;
- Connections leaking raw credentials;
- Distribution mutating runtime state outside lifecycle contracts;
- direct cross-system/workspace reads;
- any component writing another owner's private state files or DB directly.

These are **inspection obligations**, not pre-classified FORBIDDEN matrix states at A0.4.
