## 10. Readiness gate

The first-use journey does not equate installation with readiness.

After installation/setup:

1. Distribution calls composed doctor.
2. If doctor is not `ok: true`, first run returns `needs-attention`.
3. It does not return conversational handoff.
4. It does not attempt destructive repair or authority expansion.

Only a passed doctor permits:

- persisted `first_run.doctor_verified=true`;
- state `ready`;
- ordinary conversational handoff.

This is the correct public-beta readiness boundary.

## 11. Existing install handling during first use

Although A3.2 audits migration/adoption in depth, A3.1 verifies the ordinary first-use command does not silently replace an existing installation.

If a Distribution lock already exists, `aiverse start` refuses to silently change:

- profile;
- release set;
- installation root.

A previously setup install with a narrowly recognized `setup-required` Brain attachment issue may use the bounded safe reconcile contract.

- Brain attachment;
- Brain initialization;
- exact locked Brain revision;
- owner command;
- no registry lock;
- no migration.

Anything else is stopped for explicit review.
