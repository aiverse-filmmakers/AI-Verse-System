## 7. Exact-source contract

For indexed Memory exact source:

- evidence reference is mandatory;
- Memory revalidates source identity/version;
- exact source response carries exact-evidence semantics;
- stale source fails closed.

For prior-session digest evidence:

1. Memory returns external-source-required with Gateway source coverage/fingerprint;
2. Gateway resolves the exact completed run/message range;
3. Gateway revalidates system/principal/workspace visibility;
4. Gateway recomputes source fingerprint;
5. mismatch returns stale and no raw messages.

No broad transcript fallback is used when bounded source coverage is available.

## 18. Existing deep-context cache freshness defect

A2.5 proved a distinct current defect:

`WSA-2026-045` - MEDIUM.

Gateway caches repeated deep-context requests per run by request fingerprint.

For a first exact-source request:

- Memory/Gateway source freshness is correctly validated.

For a later identical request:

- Gateway can return the prior cached retrieval result;
- it may skip the owner read;
- it therefore may skip source-version/fingerprint revalidation.

If the canonical source changed between those requests, stale exact content can be replayed.

The dedicated J2 acceptance proves stale-source failure on a **fresh retrieval**, but it does not mutate the source and then issue the same exact deep request through the per-run retrieval cache.

Therefore A3.4 inherits `WSA-2026-045`; it does not open a duplicate finding.
